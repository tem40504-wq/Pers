# Закреплённый набор v9.2

Цель: Windows 10/11 x64, обычный CPython 3.13. Для установщика закреплён Python 3.13.14. ARM64 и free-threaded Python не входят в этот профиль.

## Что проверено

Все 17 файлов полностью скачаны. Для 14 wheel-пакетов SHA-256 сверен с JSON-метаданными PyPI. Для Python SHA-256 сверен со страницей официального выпуска. Для scrcpy SHA-256 сверен с официальным GitHub Release. Для ADB сверен опубликованный Google SHA-1 и размер, затем рассчитан SHA-256 для последующих загрузок. Версия ADB сверена по source.properties внутри архива.

Точные URL, версии, размеры, хеши, источники и зависимости файлов сохранены в `bootstrap/verification_windows.json`. Установка не использует URL вида «latest». Получение файла и его контрольная сумма подтверждают целостность, но не заменяют проверку исполнения на Windows.

В базовом профиле NumPy 2.2.6, OpenCV 4.12.0.88, Pillow 12.0.0, Requests 2.32.5 и все зависимости Requests; отдельно тестовый профиль с pytest 8.4.2 и его зависимостями. ADB 37.0.1 и scrcpy 5.0.1 закреплены для Windows.

## Простой запуск испытаний

1. Распакуйте архив целиком на Windows.
2. Если Python 3.13 x64 ещё не установлен, используйте официальный файл по URL из строки `python` манифеста. SHA-256 должен совпасть. EXE запускается вручную; обычная установка с Python Launcher достаточна.
3. Запустите `RUN_WINDOWS_TESTS.bat`.
4. Прочитайте список операций и введите `Y`. Будут загружены проверенные wheel-файлы и ADB, создана `.venv` внутри проекта и установлены локальные зависимости. Драйвер NVIDIA не изменяется.
5. Дождитесь завершения. Откройте `reports/windows_test_report.json`; журналы и JUnit лежат рядом.

Команды для тех же действий:

```powershell
py -3.13 run_windows_tests.py --prepare
```

Для проверки подключённого Samsung без касаний:

```powershell
py -3.13 run_windows_tests.py --prepare --phone
```

Телефон должен быть подключён и авторизован через USB-отладку. `--phone` выполняет только три цикла наблюдения. Команда не проверяет боевые действия, производительность GPU или полноценную автономную игру.

`--yes` означает явное согласие на подготовку без интерактивного вопроса и предназначен в том числе для CI. Без `--prepare` ничего не скачивается и не устанавливается.

## Испытания через GitHub Actions

Готов файл `.github/workflows/windows-tests.yml`: Windows Server 2022 x64, Python 3.13.14, загрузка закреплённых файлов, pip check, импорт библиотек, запуск adb.exe, тесты Level 9/Level 8, отчёты как артефакт.

Для исполнения проект должен быть размещён в выбранном репозитории с включёнными GitHub Actions. Проверка на Windows Server 2022 не заменяет проверку Windows 10/11 на пользовательском ПК. На облачном runner нет Samsung или RTX пользователя, поэтому аппаратные испытания остаются отдельными.

## Установка профилей отдельно

```powershell
py -3.13 -m bootstrap.bootstrap --profile windows-base --create-venv
py -3.13 -m bootstrap.bootstrap --profile windows-tests --create-venv
py -3.13 -m bootstrap.bootstrap --profile windows-screen
```

Каждый профиль показывает список операций перед установкой. Повторная распаковка ZIP в уже существующую целевую папку через обычный bootstrap блокируется. Тестовый runner допускает повторную подготовку своей локальной папки ADB после проверки исходного ZIP.

## Аудит дополнений и реальное исполнение

Базовый CI выполнен успешно: https://github.com/tem40504-wq/Pers/actions/runs/37978533875 . Windows Server 2022 x64 / CPython 3.13.14, pip check, импорты, adb.exe и тесты. Это не испытания на ПК/телефоне владельца.

Все 44 дополнительные позиции рассмотрены. Для 37 закреплены файлы или полные комплекты; 7 ограничены оборудованием, совместимостью либо отсутствием весов. См. `OPTIONAL_AUDIT_RU.md` и `bootstrap/verification_optional_windows.json`.

Для семи библиотек есть замкнутый дополнительный профиль и проверка исполнения:

```powershell
py -3.13 run_windows_tests.py --prepare --optional-smoke
```

Остальные дополнительные wheel, системные EXE и комплекты VLM автоматически не устанавливаются: их полный runtime и интеграция требуют отдельных испытаний. Реестр проверяет все сопутствующие файлы VLM, а не только первый shard.
