# Universal Game Agent — Level 5+ | архитектура интеграции

## Принцип: никаких замен уровня 4

Версия построена как **слой поверх реального Level 4.1 PermissionGate**, а не как новая реализация Level 3.

```text
[Android через прежний ADB] --> [Perception L3/L4] -----+
                                                        |
[Разрешённый аудио PCM] --> [AudioPerception] --+         |
                                               v         v
                               [SwarmBus и L4 Manager/Worker/TemporalBrain]
                                               |
                                    [DSL + Voyager SkillRegistry]
                                               |
                           [WorldModel + rollout 6 (5-10) шагов]
                                               |
                           [OperatorAssistant: корректировка]
                                               |
                           [PanicExecutor -> ActionExecutor L3]
                                               |
                                          [ADB/HID L4]
                                               |
                                  [ChromaDB + Memory L3]

                 [XAI Dashboard (localhost)] <--- наблюдения и сводки
                       | PANIC STOP (threading.Event)
                       +-------------> [PanicExecutor + цикл L5]
```

Резервные пути: `main.py` (L3), `main_l4.py` (L4). Оригинальные `GameAgent.step`, `Level4Agent.choose_action`, `brain.py`, `action.py`, `perception.py`, `memory.py`, `dsl.py`, `swarm.py` остаются без изменений. Интеграция через `Level5Agent` и обёртку `AudioSwarmAdapter`.

## Состав файлов (все новые, кроме security.py)

- `game_agent/l5/world_model.py`: эмпирическая модель переходов, прогнозы и 5–10 шагов модельного планирования. Требует реальных действий с обратной связью и калиброванного HP.
- `game_agent/l5/rssm.py`: экспериментальная Torch GRU (RSSM-lite), не DreamerV3. Используется только после независимой валидации; не загружается автоматически.
- `game_agent/l5/audio.py`: AudioPerception, утверждённый аудиоисточник и TFLiteYAMNetAdapter; нет скрытого включения микрофона.
- `game_agent/l5/meta_adapter.py`: 5–10 размеченных областей -> цветовые Lab-прототипы. Это надстройка, а не изменение весов исходного YOLO.
- `game_agent/l5/behavior.py`: ограниченное синтезирование траекторий и экспериментальный GAN только для офлайн UX-тестов. Никаких гарантий неотличимости/обхода защит.
- `game_agent/l5/operator.py`: OperatorAssistant (уровни 0..3, проверяемые объяснения, feedback, подсказки).
- `game_agent/l5/dashboard.py`: localhost FastAPI, кадры с bboxes, решения, журнал, SwarmBus, PANIC STOP.
- `game_agent/l5/agent_l5.py`: наследник Level4Agent; дополнительные hooks, наблюдение и перехват отправки команд.
- `main_l5.py`: безопасный entrypoint и запросы PermissionGate.
- `START_L5_SAFE.cmd`: Windows запускает только Python; ничего не ставит без явного Y.
- `game_agent/l4/security.py`: **добавлены только фиксированные белые списки зависимостей**, прежний PermissionGate неизменён.

## Компоненты

### WorldModel / Planning

Базовая модель — непараметрическая оценка сдвига `GameStateVector` по ключу доверенного действия. Для каждого перехода проверяется временной порядок, диапазон и наличие фактических числовых сигналов. При недостатке выборки fallback возвращает **старое** действие. На 5–10 шагах сравнивается ограниченная полезность (выживание/риск); расчёт не придумывает незарегистрированных действий и не гарантирует достижение целей.

RSSM-lite — Torch GRU для обучения на отдельных эпизодах. Для тренировочных сессий используйте последовательности `[batch, time, hp/mp/distance/threat + one_hot_action]` и следующий вектор. Перед включением: независимый game/session split, проверка MAE, калибровка ошибок, drift detection и безопасный offline rollout. DreamerV3 потребует отдельно обучения визуального encoder, стохастической динамики и actor/critic и в архив **не входит**.

### AudioPerception

Стандартный `adb exec-out` отдаёт видео/скриншоты, но нет универсального потокового ADB-интерфейса Android internal audio. Разрешённый источник: заранее выбранный аудиовход ПК (в том числе loopback, если поддерживается драйвером). `sounddevice` и `tflite-runtime` не устанавливаются автоматически; активный аудиозахват требует отдельного Y. В модели должны быть **проверенные классы**, поскольку YAMNet классифицирует общие звуки, а не игровые предупреждения как таковые. При отсутствии модели возвращаем пустой список событий. Аудиоклассификация выполняется в отдельном потоке; `AudioSwarmAdapter` публикует оповещения в существующий SwarmBus. Команды движения по одному аудио сигналу не выполняются.

### MetaAdapter / MAML

Реализован быстрый неразрушающий `MetaAdapter` для цветовых прототипов UI. Он требует 5–10 **размеченных** областей; это не полное MAML. Для настоящего MAML/ANIL:
1. Набрать много игровых доменов и train/test эпизодов с поддержкой и запросами.
2. Получить meta-initialization для детектора UI, затем inner-loop 1–5 градиентных шагов на support 5–10 кадров.
3. Оценить на query и unseen games без утечки кадров из того же эпизода.
4. Сохранять game-specific LoRA/adapter отдельно от исходных весов и откатывать при drift.

Заявленные 2–3 минуты зависят от GPU и качества предобученных весов; гарантии нет.

### Behavioral generator

Содержит bounded trajectory synthesis, опциональную обучаемую PyTorch GAN по **согласованным** пользовательским траекториям. Примерный GAN предназначен для анализа жестов в UX-тестах, а не скрытия автоматизации или обхода античита. Стандартный ADB `input swipe` не воспроизводит непрерывную кривую Безье; отдельный HID-инжектор потребует проверенных прав, калибровки и прежнего safety gate.

### XAI Dashboard / OperatorAssistant

Панель слушает только `127.0.0.1` и требует токен в POST-запросах. HTML статический (без внешних CDN). Частота обновления ~1 Гц; это не 30 FPS, реальный предел зависит от ADB и CV. В панели показываются **результат принятия решения, наблюдаемые факторы и обоснования**, не скрытая внутренняя цепочка мыслей VLM.

`OperatorAssistant` отвечает на вопросы по последнему наблюдению и состоянию. Уровни: 0 действия; 1 краткое обоснование; 2 прогнозы; 3 диагностические факты. Можно изменить текстовой командой `уровень 2` или через панель. Аудиораспознавание команд намеренно не включено: оператор может подать транскрипт только после отдельного разрешения.

Команды `Не пей зелье, беги!` временно блокируют любое действие, пока не подтверждён безопасный навык отхода; агент не угадывает координаты и не нарушает Skill Library. Подсказки новых механик требуют OCR с высокой уверенностью, повторённый >=3 раза; гипотеза обозначается как требующая проверки.

### PANIC STOP

`XAI_Dashboard.stop()` делает `threading.Event.set()`; `PanicExecutor` проверяет флаг **до** каждой передачи команды старому исполнителю. Цикл `Level5Agent.run` проверяет флаг между шагами и прерывает паузу методом Event.wait. Уже отправленный USB/HID жест нельзя гарантированно прервать, а долгий VLM вызов может закончиться позже. Поэтому не обещайте миллисекундную остановку существующего действия; для аппаратной emergency-stop нужен отдельный аппаратный размыкатель.

## Безопасность

- Запуск Level 5 не требует установки нового APK на телефон.
- `PermissionGate` из Level 4 **остаётся**, дополнительные пакеты внесены в белый список.
- Нет `pip install`, `ollama pull`, EXE-загрузок, изменения Windows Settings **без явного разрешения**. При `N` необязательный модуль отключается.
- В `--preflight-only` телефон не используется. В обычном безопасном запуске `--execute` не задан.
- Веса, аудиооборудование и отправка облачного видео не включаются без согласия.
- Панель только localhost, с токеном на мутационные запросы; не открывать порт в Интернет.
- Как и L4, Python-процесс не является OS sandbox. Недоверенные сторонние плагины необходимо проверять отдельно.

## Возможные bottlenecks

| Риск | Снижение | 
|---|---|
| ADB-скриншот и OCR >500 мс | Worker period — целевой, а не жёсткий real-time deadline |
| Высокая latency TFLite YAMNet | Отдельный AudioWorker, очередь maxsize=3 и drop-oldest |
| Неверное сопоставление классов YAMNet | Проверенный class-map + threshold + явное отключение при неизвестном экспорте |
| Ложная динамика HP и reward hacking | Минимум наблюдений, confidence floor, безопасный fallback |
| Сверхэкстраполяция rollout | Ограничение horizon 5–10, штраф неопределённости и симуляция только известных навыков |
| GPU конкуренция RSSM/LocalVLM/GAN | Обучение офлайн, CPU/batch limits, GPU profiling |
| Задержка объяснения относительно кадра | scene_id/timestamp для каждого наблюдения, рендеринг после принятия решения |
| Потери сообщений аудио/роя | TTL по сцене, capacity ограничен, high priority alerts |
| Ошибочный голосовой ввод | Выключен по умолчанию, проверять текст до выполнения |
| Panic во время USB жеста | Пред-исполнительный шлюз + аппаратная остановка для настоящей мгновенной реакции |

## Переходы L4 -> L5

`Level5Agent.choose_action()` запускает родительский Level4Agent: извлечение GameStateVector, TemporalPredictor, Swarm+DSL+fallback. Затем WorldModel может оценить подтверждённые candidate Actions; пока модель не обучена, она ничего не меняет. После операторского ограничения выполняется **старый ActionExecutor**, обёрнутый PanicExecutor. `Level5Agent.step()` вызывает оригинальный `GameAgent.step()`, и лишь после исполненного действия считывает дополнительный кадр для онлайн обновления модели мира. Существующие ChromaDB/рефлексия/skill library остаются нетронутыми.
