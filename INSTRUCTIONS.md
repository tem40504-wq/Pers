# Игровой агент v9.5 — восстановление ADB

Исправление уже внедрено в main_pc_l9.py. Запускать patch_main_pc_l9.py дополнительно не нужно.

1. Распакуй архив в новую папку. Не запускай из ZIP.
2. Запусти RUN_WINDOWS_TESTS.bat, подтверди Y и дождись Exit code: 0.
3. Подключи разблокированный телефон с включённой USB-отладкой. Подтверди разрешение отладки, если появится запрос.
4. Запусти VERIFY_ADB.bat. Ожидается 20 успешных скриншотов, 0 провалов, Exit code: 0. Касаний нет.
5. Если тест падает, запусти VERIFY_ADB_PULL.bat. Он сразу использует файл на телефоне и ADB pull, без потокового exec-out.
6. Для обычного запуска открой игру и запусти start_agent.bat. Для запуска сразу через файл — START_AGENT_PULL.bat.

При потере телефона наблюдение переходит в паузу. При восстановлении продолжает работу. При истечении таймаута завершает сессию с понятной ошибкой ADB, без старого трейсбека.
Попытки восстановления внутри получения скриншота тоже занимают время: общий срок может превышать 60 секунд.

PANIC STOP сохраняет остановку. В реальном режиме с касаниями обрыв завершает сессию: действие могло уже выполниться, повторять его автоматически нельзя.

## Диагностика

Лог: logs/adb_bridge.log (10 МБ × 5 архивов).
Отчёт проверки телефона: reports/adb_verify_report.json.
Если не получилось, пришли этот отчёт и лог.

Дополнительно в cmd из папки проекта:

```bat
.venv\Scripts\python.exe verify_adb.py --no-input --stress
```

После 10-го снимка будет пауза 5 секунд: можно отключить и подключить кабель. Не расшатывай разъём.

Реальный тест касаний выполняется только с --input. Перед ним открой нейтральный экран телефона:

```bat
.venv\Scripts\python.exe verify_adb.py --input
```

Будут выполнены tap 100 200 и swipe 100 200 300 400 300. Успешный ответ означает принятие команды ADB, а не проверку поведения игры.

## Что проверить

Кабель с передачей данных, прямой USB-порт, включённая отладка, авторизация телефона. Зарядка не доказывает передачу данных. На время проверки закрой другие ADB-программы. При исчезновении телефона проверь Диспетчер устройств.
«Не выключать экран» при зарядке полезно для диагностики, но не исправляет кабель/драйвер. Не меняй питание всех USB-устройств без необходимости.

Мост сохраняет serial телефона и не переключается автоматически на другой аппарат. Перезапуск ADB-сервера затрагивает другие ADB-программы; частые перезапуски ограничены.

Сохранена полная проверка PNG: CRC, границы блоков, IEND и декодирование пикселей Pillow. Маленький корректный PNG допустим. После успешного резервного pull этот способ используется до конца сессии. Временные имена уникальны.

Проверки CI выполняются на Windows Server 2022 / Python 3.13.14. Реальная USB-передача на твоём Samsung проверяется отдельно через VERIFY_ADB.bat.

Документация: https://developer.android.com/tools/adb
Драйвер Samsung: https://developer.samsung.com/android-usb-driver
